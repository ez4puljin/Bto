# Заавар: төв системийг дэлгүүрийн Ubuntu компьютерт суулгах (ADR-0186)

Энэ бол `store-install.md`-ийн монгол хувилбар.

Гадаад сервер бэлэн болох хүртэл төв систем (өгөгдлийн сан, api, worker, вэб хуудас) дэлгүүрийн Ubuntu компьютер дээр, касс edge-ийн хажууд ажиллана. Энэ заавар суулгах, үндсэн өгөгдлийг хуулах, edge-ийг шилжүүлэх, нөөцлөх, туршилтын өдөр, шинэчлэх, буцаах, компьютер эвдрэх үеийг хамарна. Тусгайлан «эзэмшигчийн компьютер дээр» гэж бичээгүй бол командуудыг дэлгүүрийн компьютерт, repo-гийн хавтсанд (`~/bto`) ажиллуулна.

**Алхам бүрт мөрдөх дүрэм.**

- `docker compose … down -v` болон `docker volume rm` командыг хэзээ ч бүү ажиллуул. Volume гэдэг нь өгөгдлийн сан өөрөө юм.
- `.env` файлын утгыг чат, баримт бичиг, repo-д бүү хуул (repo нээлттэй).
- Систем зөвхөн дэлгүүрийн дотоод сүлжээнээс нээгдэнэ. Router дээр түүн рүү порт бүү нээ.
- Энэ систем дээр туршилтын борлуулалт хийхгүй. Энд зарсан бүхэн жинхэнэ борлуулалт.

| | |
|---|---|
| Компьютер | `bto-edge@192.168.1.152`, Ubuntu, Docker; нэг диск |
| Ажилтан нээх хаяг | `http://192.168.1.152` (порт 80) |
| Кассын хаяг | `http://192.168.1.152:7400` (`/K1` …), өмнөх шигээ |
| Stack | `bto-store` (`deploy/store`: `postgres`, `api`, `worker`, `web`) ба `bto-edge` (`deploy/edge`: `edge-db`, `edge`, `kiosk`) |
| Нууц утгууд | Компьютер дээрх `deploy/store/.env`, `deploy/edge/.env` (скрипт үүсгэнэ, зөвхөн эзэмшигч уншина) |
| Нөөц | Компьютер дээр `/var/backups/bto`; USB диск `/mnt/bto-backup`; эзэмшигчийн компьютерт `Documents\Bto-backups\store` |

Доорх командуудад хоёр товчлол хэрэглэнэ:

```bash
S="docker compose -f deploy/store/docker-compose.store.yml --env-file deploy/store/.env"
E="docker compose -f deploy/edge/docker-compose.edge.yml --env-file deploy/edge/.env"
```

## 1. Суулгахын өмнө

1. **Тогтмол хаяг.** Router дээр `192.168.1.152` хаягийг энэ компьютерт бэхэлнэ (DHCP reservation). Касс, утас, оффисын компьютер бүр энэ хаягийг ашиглана.
2. **Хоёр талд ижил хувилбар.** Эзэмшигчийн компьютерийн үндсэн хавтас хамгийн сүүлийн `main` дээр, dev өгөгдлийн сан нь шинэчлэгдсэн (`pnpm db:migrate`) байна. Дэлгүүрийн компьютерт: `cd ~/bto && git pull`. Тэнд байгаа `deploy/edge/..env.swp` файлд бүү хүр.
3. **Ажлын бус цагаар.** Эхний бүтээлт 10–20 минут үргэлжилж, компьютерийн санах ойн ихэнхийг эзэлнэ.
4. **Дискний сул зай.** `df -h /` 30 GB-аас их байх ёстой. Бага бол эхлээд `bash deploy/store/housekeeping.sh` (хуучин build cache 40 орчим GB).

## 2. Төв системийг суулгах

```bash
cd ~/bto
bash deploy/store/setup.sh
sudo ufw allow 80/tcp        # нэг удаа: галт хана идэвхтэй; edge ч төв рүү энэ портоор хандана
```

Скрипт Docker-ийг шалгаж, `deploy/store/.env`-ийг шинэ нууц утгуудтай үүсгэнэ (дэлгэцэд гарахгүй). Дараа нь хоёр image-ийг бүтээж, өгөгдлийн санг асааж, эрх ба хүснэгтүүдийг бэлтгэнэ. Өгөгдлийн сан хоосон бол скрипт **энд зогсож**, дараагийн алхмыг хэлнэ: систем асахаас өмнө үндсэн өгөгдлийг хуулна (3-р хэсэг).

Хоосон системээр эхлэх бол `bash deploy/store/setup.sh --start` гээд анхны админыг үүсгэнэ:

```bash
$S run --rm --no-deps api node dist/modules/identity/cli/create-admin.js --phone <утас> --full-name "<нэр>"
```

Команд 30 минут хүчинтэй нэг удаагийн код хэвлэнэ. Тэр хүн `http://192.168.1.152/set-password` хуудсанд («Нэг удаагийн кодоор нууц үг тохируулах») нууц үгээ тохируулна.

## 3. Үндсэн өгөгдлийг dev сангаас хуулах (эзэмшигчийн компьютер дээр)

Юу хуулагдах, юу хуулагдахгүйг ADR-0186-ийн 7-р зүйл болон туршилтын ажиллуулалтын жагсаалт харуулна. Баримт, үлдэгдэл, журнал, түүх хэзээ ч хуулагдахгүй.

1. **Дэлгүүрийн компьютерийн өгөгдлийн сан руу хонгил нээнэ.** Хоёр дахь PowerShell цонхонд ажиллуулаад 5-р алхам дуустал нээлттэй үлдээнэ:

   ```powershell
   ssh -N -L 25433:127.0.0.1:15433 bto-edge@192.168.1.152
   ```

2. **Зорилтот сангийн хаягийг нууц үгийг нь харуулалгүй тохируулна.** Үндсэн хавтсанд (`pnpm dev` ажиллаж байж болно, гэхдээ хуулах хооронд хэн ч бараа, харилцагчийн мэдээлэл засахгүй):

   ```powershell
   $pw = ssh bto-edge@192.168.1.152 "grep '^MIGRATOR_DB_PASSWORD=' ~/bto/deploy/store/.env | cut -d= -f2-"
   $env:SEED_TARGET_DATABASE_URL = "postgres://migrator:$pw@127.0.0.1:25433/bto"
   ```

3. **Туршилтын ажиллуулалт.** Юу ч бичихгүй, гурван жагсаалт ба саадыг харуулна:

   ```powershell
   pnpm store:seed
   ```

   - «NOT DECIDED» хүснэгтүүд хоосон үлдэнэ. Тэдгээрийг эзэмшигч дараа нь тусад нь шийднэ.
   - «the two databases are on different migrations» гэвэл 1-р хэсгийн 2-р алхмыг хийнэ.
   - «the target is not empty» гэвэл дэлгүүрийн систем аль хэдийн ассан байна. «Алдаа гарвал» хэсгийг үз.

4. **Хуулах**, мөн зөөх файлуудын жагсаалтыг гаргах:

   ```powershell
   pnpm store:seed --apply --files-list ../../tmp/store-seed/files.txt
   ```

   `Copied … rows into 98 tables` гэж дуусна. Саад гарвал юу ч бичигдэхгүй.

5. **Файлуудыг зөөнө** (барааны зураг, ажилтны зураг, нийтэлсэн APK; 3 орчим GB, хэдэн минут). Дараа нь нууц үгийг санах ойгоос арилгаж, хонгилын цонхыг хаана:

   ```powershell
   cmd /c "tar -C .data\storage -cf - -T tmp\store-seed\files.txt releases | ssh bto-edge@192.168.1.152 ""docker run --rm -i -v bto-store_storage:/data/storage bto-api:store-local tar -xf - -C /data/storage"""
   Remove-Item Env:SEED_TARGET_DATABASE_URL; Remove-Variable pw
   ```

   `.data\storage\releases` хавтас байхгүй бол командаас `releases` гэдэг үгийг хасна.

6. **Төв системийг асаана** (дэлгүүрийн компьютер дээр): `bash deploy/store/setup.sh`. Одоо үндсэн өгөгдөл байгаа тул бүгдийг асаана. `http://192.168.1.152/system/status` хуудсыг нээж шалгана.

7. **Анх нэвтэрсний дараа админ шууд хийх зүйлс:**
   - Бүх хүн dev систем дээрх нууц үгээрээ нэвтэрнэ. Хамт хуулагдсан **туршилтын нэвтрэх нэрсийг идэвхгүй болгоно** («Ажилтан» жагсаалт). Админуудын dev нууц үг энгийн байсан бол солино.
   - «Тохиргоо → AI»: AI түлхүүрийг дахин оруулна (түлхүүр хуулагддаггүй).
   - «Компани»: компанийн регистр, ТТД-г шалгана.
   - Үлдэгдэл бүх газар тэг, нэг ч баримт байхгүй. Нэг бараа, нэг харилцагч, нэг үнийг нээж шалгана.

## 4. Нөөцлөлт (суулгасны дараа нэг удаа тохируулна)

```bash
sudo bash deploy/store/install-backup-timer.sh     # шөнө бүр 02:30-д; алгассан бол асмагц
sudo systemctl start bto-backup.service            # одоо нэг удаа ажиллуулах
cat /var/backups/bto/last-run.txt
```

Нэг шөнийн хавтас `/var/backups/bto/daily/<огноо>_<цаг>` дотор:

- `centre.dump`, `edge.dump`: хоёр өгөгдлийн сангийн хуулбар;
- `globals.sql`: өгөгдлийн сангийн эрхүүд;
- `counts-*.tsv`: хүснэгт бүрийн мөрийн тоо;
- `store.env`, `edge.env`, `commit.txt`, `SHA256SUMS`.

`/var/backups/bto/storage` нь оруулсан файлуудын хуулбар. Компьютер дээр 14 хоног хадгална (`deploy/store/.env`-ийн `BACKUP_KEEP_DAYS`).

**Компьютер нэг дисктэй. Тэр диск дээрээ үлдсэн нөөц нөөц биш.** Хоёр хуулбар компьютерээс гарна:

- **USB диск.** Дискийг ext4-өөр форматлаад `/mnt/bto-backup`-д байнга холбоно (`/etc/fstab`-д `nofail` сонголттой мөр). Шөнө бүрийн хавтас ба файлын хуулбар тийш хуулагдаж, 90 хоног хадгалагдана. Диск холбогдоогүй бол `last-run.txt`-д «USB: NOT copied» гэж гарна. Диск дээр бүх өгөгдөл, нууц утгууд байгаа тул түгжээтэй газар хадгална.
- **Эзэмшигчийн компьютерээс татах** (долоо хоногт дор хаяж нэг, туршилтын үед өдөр бүр):

  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File tools\store-backup\pull.ps1            # хамгийн сүүлийн шөнө
  powershell -NoProfile -ExecutionPolicy Bypass -File tools\store-backup\pull.ps1 -Storage   # мөн сүүлд нэмэгдсэн файлууд
  ```

  Скрипт сүүлийн нөөцлөлтийн дүнг харуулж, хамгийн сүүлийн шөнийг `Documents\Bto-backups\store` руу татаж, файл бүрийг шалгах нийлбэртэй нь тулгана. Энэ хавтсыг үүлэн сантай (OneDrive, Google Drive) синк хийдэг газар бүү байрлуул.

**Сэргээх сургуулилт** (суулгасны дараа, дараа нь улирал бүр, нөөцлөлтөд өөрчлөлт орсон бүрд). Хамгийн сүүлийн шөнийг жинхэнэ сангийн хажууд түр санд сэргээж, хүснэгт бүрийг нөөцлөх үеийн тоотой тулгаад түр санг устгана:

```bash
sudo bash deploy/store/restore-drill.sh
```

`DRILL OK` гэвэл нөөц бүрэн. `FEWER`, `MISSING` мөр гарвал аль хүснэгт дутуу байгааг заана.

**Дискний цэвэрлэгээ.** Шинэчилсний дараа `df -h /` 30 GB-аас бага бол `bash deploy/store/housekeeping.sh`. Нөөцлөлт ням гараг бүр build cache-ийг өөрөө цэвэрлэнэ. Volume-д хэзээ ч хүрэхгүй.

## 5. Edge-ийг шинэ төв рүү шилжүүлэх

Дэлгүүрийн компьютерийн edge одоо эзэмшигчийн компьютер дээрх dev төвтэй холбоотой туршилтын edge. Түүнийг **өгөгдлийн сангийн сервер дотроо шинэ, хоосон сантай** болгож жинхэнэ edge болгоно. Юу ч устахгүй: хуучин сангийн нэрийг сольж, дахин нээхгүй. Өдрийн эхэнд, анхны борлуулалтаас өмнө хийнэ (өдрийн баримтын дугаар дахин эхэлнэ).

1. Dev төвийн «Супермаркет → Пос» хуудсанд бүх ээлж хаагдсан, edge-ийн «Илгээгээгүй» 0 байгааг шалгана. Татгалзсан 13 туршилтын баримт хуучин сандаа үлдэнэ.
2. Edge ба кассын хуудсыг зогсооно, өгөгдлийн сан нь ажилласаар байна:

   ```bash
   $E stop kiosk edge
   ```

3. Хуучин сангийн нэрийг сольж, хоосон сан үүсгэнэ (нэр дэх огноо нь тухайн өдөр):

   ```bash
   $E exec -T edge-db psql -U edge -d postgres -c "ALTER DATABASE tugeel_edge RENAME TO tugeel_edge_dev_20261111"
   $E exec -T edge-db createdb -U edge -T template0 -E UTF8 tugeel_edge
   ```

4. Холболт файлаас биш, кассын хуудаснаас хийгдэх ёстой. `deploy/edge/.env` дотор `CENTRAL_API_URL=`, `EDGE_NODE_TOKEN=`, `POS_PIN_PEPPER=` гурван мөр хоосон, `EBARIMT_PROVIDER=fake` байна. Файлыг засварлагчаар нээж харна, дэлгэцэд бүү хэвлэ.
5. Edge-ийг дахин асаана. Хоосон сангаа өөрөө бэлтгэж, кассын хуудас «Төв системтэй холбох» дэлгэцийг харуулна:

   ```bash
   bash deploy/edge/setup.sh
   ```

6. Edge нэг компьютер дээрх төв рүү хүрч байгааг шалгана:

   ```bash
   $E exec -T edge node -e "fetch('http://host.docker.internal/health').then((r)=>r.text()).then(console.log)"
   ```

   `{"status":"ok",…}` гэж гарна. Холбогдохгүй бол `sudo ufw allow 80/tcp` (2-р хэсэг). Тэгээд ч болохгүй бол энэ хэсгийн төгсгөлийн нөөц аргыг хэрэглэнэ.
7. Шинэ төв дээр (`http://192.168.1.152`) «Супермаркет → Пос» → edge серверийн мөр → «Холбох код». `http://192.168.1.152:7400` дээр: «Төв системийн хаяг» нь `http://host.docker.internal`, дараа нь edge серверийн код, холбох код.
8. Кассын компьютер бүр өөрийн хаягаа нээнэ (`http://192.168.1.152:7400/K1`, ADR-0138). Үүнээс өмнө кассчдын PIN-ийг тохируулна (6-р хэсэг).

**6-р алхам бүтэхгүй үеийн нөөц арга.** Edge-ийг төвийн Docker сүлжээнд нэгтгэж, төвийн хаягт `http://api:3000` гэж бичнэ. Ингэж асаасан edge-ийг дараа нь мөн энэ командаар шинэчилнэ, зөвхөн `deploy/edge/setup.sh`-ээр биш:

```bash
docker compose -f deploy/edge/docker-compose.edge.yml -f deploy/store/docker-compose.edge-link.yml --env-file deploy/edge/.env up -d
```

## 6. Туршилт: нэг касс

**Өдрөөс өмнө (эзэмшигч).**

- [ ] **Үлдэгдэл.** Одоо тэг. Супермаркетын заалыг «Тооллого»-оор тоолно, эсвэл эхний үлдэгдлийг импортоор оруулна. Касс үлдэгдэлгүй гэж борлуулалтаас хэзээ ч татгалздаггүй: тоолоогүй бараа зарагдаад няравт «Дутагдал» мөр үүсгэнэ. Тиймээс эхлээд тоолно.
- [ ] **Санхүүгийн бүртгэл.** Одоо хоосон. Эхний үлдэгдлийг нягтлан шилжилтийн үед оруулна. Туршилтын борлуулалт Bto-гийн бүртгэлд бичигдэнэ, харин албан ёсны бүртгэл Эрхэт хэвээр байна. Шилжилтийн үед энэ хоёрыг хэрхэн нийлүүлэхийг нягтлан шийднэ (architecture §13.2 T41). Өдрөөс өмнө нягтлангаас асууна.
- [ ] «Супермаркет → Пос»: туршилтын пос (К1)-ын принтер, мөнгөний хайрцаг, баримтын загвар, зөвшөөрөгдсөн кассчид, төлбөрийн төрлүүд.
- [ ] «Супермаркет → Кассчин»: **кассчин бүрт шинэ PIN** (PIN хуулагддаггүй).
- [ ] Кассын компьютер: Chrome дээр `http://192.168.1.152:7400/K1` хаягийн товчлол, баримтын принтер ба мөнгөний хайрцаг (`pos-till-printing.md`), сканнер. PIN-ээр нэвтэрч, бараа хайж, «Үнэ шалгах»-ыг ашиглаж, принтерийн туршилтын хуудас хэвлэнэ. **Борлуулалт хийхгүй.**
- [ ] Анхны нөөцлөлт ажилласан, сэргээх сургуулилт `DRILL OK` гэсэн (4-р хэсэг).

**Тухайн өдрийн өглөө.**

- [ ] **И-баримтын тохиргоог солино.** `deploy/edge/.env` дотор `EBARIMT_PROVIDER=posapi`, `POSAPI_URL=http://192.168.1.254:7080`, `EBARIMT_BRANCH_NO=<хуучин кассын баримт дээрх салбарын дугаар>` гэж бичээд `bash deploy/edge/setup.sh`. **Энэ мөчөөс баримт бүр татварын жинхэнэ баримт болно.** Edge PosAPI-д хүрсэн бол «Супермаркет → Пос» хуудсанд PosAPI-ийн хувилбар, үлдсэн сугалааны тоо харагдана.
- [ ] Ээлжийг эхний мөнгөтэй нээнэ. Анхны борлуулалтын баримт ДДТД, сугалааны дугаар, QR-тай хэвлэгдэнэ. Төв дээр «Борлуулалт» жагсаалтад баримтын төлөвтэйгөө харагдана.

**Орой бүр.**

- [ ] Ээлжийг тоолсон бэлэн мөнгөөр хааж, зөрүүг харна.
- [ ] «Супермаркет → Пос»: «Илгээгээгүй» 0, татгалзсан баримт 0, PosAPI-ийн сүүлд илгээсэн огноо өнөөдөр (биш бол «Татвар руу илгээх»).
- [ ] «Дутагдал»: тухайн өдрийн мөрүүдийг нярав харна.

## 7. Шинэчлэх (main руу push хийсний дараа)

Эзэмшигчийн дүрэм (2026-11-11, «Push бүрийн дараа»): push хийсэн кодын өөрчлөлт бүрийг тэр дор нь дэлгүүрийн компьютерт оруулна, эхлээд төвийг. Зөвхөн баримт бичиг өөрчилсөн push-д шинэчлэл хэрэггүй. Сешн үүнийг SSH-ээр, `sudo`-гүйгээр хийнэ (`git pull --ff-only && bash deploy/store/setup.sh && bash deploy/edge/setup.sh`). Оффисын дэлгэц 1–2 минут, кассууд 1 минут зогсдог тул том өөрчлөлтийг ачаалал багатай үед push хийвэл зүгээр. Шөнийн нөөцлөлтийн цаг тохируулаагүй үед доорх нөөцийн мөрийн оронд `BACKUP_DIR=$HOME/bto-backups bash deploy/store/backup.sh` (`sudo`-гүй, зургийн хуулбаргүй) ажиллуулна.

```bash
cd ~/bto
sudo systemctl start bto-backup.service && cat /var/backups/bto/last-run.txt
git pull
bash deploy/store/setup.sh      # бүтээж, хүснэгтүүдийг шинэчилж, дахин асаана (оффисын дэлгэц 1–2 минут зогсоно)
bash deploy/edge/setup.sh       # дараа нь edge ба кассын хуудас (кассууд 1 минут зогсоно)
```

`http://192.168.1.152/system/status` шинэ хувилбарыг харуулна. Лог: `$S logs -f --tail 100 api` (эсвэл `worker`, `web`, `postgres`).

## 8. Буцаах

**Хурдан арга (ADR-0196), шинэчлэлтийн дараа ямар нэг зүйл эвдэрвэл:**

```bash
cd ~/bto
bash deploy/store/rollback.sh      # өмнөх шинэчлэлтийн image, хагас минутад буцна
curl -s http://127.0.0.1/health    # одоо ямар хувилбар ажиллаж байгаа
```

Энэ нь зөвхөн ажиллаж буй системийг буцаана: кодын хуулбар шинэ хэвээр үлддэг тул дараагийн `setup.sh` шинэ кодыг дахин бүтээнэ — эвдрэлийг олж засаад push хийнэ. Хоёр хувилбарын хооронд өгөгдлийн сангийн шилжилт хийгдсэн бол татгалзана (`--force` өгвөл үргэлжилнэ), учир нь хуучин код шинэ хүснэгттэй тохирохгүй байж магадгүй; тэр тохиолдолд шөнийн нөөцлөлт (9-р хэсэг) зөв хариу.

**Гараар, хадгалагдсан image байхгүй бол (компьютер дээрх анхны шинэчлэлт):**

- **Код.** Шинэчлэлт хүснэгтэд өөрчлөлт оруулаагүй бол (`git diff --stat <хуучин> <шинэ> -- apps/api/src/db/migrations` хоосон): `git checkout <хуучин commit>`, хоёр setup скриптийг дахин ажиллуулна. Засвар бэлэн болмогц `git checkout main`.
- **Хүснэгт өөрчлөгдсөний дараа** хуучин код шинэ хүснэгттэй таарахгүй байж болно. Урагшаа засна (main-д шинэ commit, 7-р хэсэг). Эцсийн арга бол өнгөрсөн шөнийн өгөгдөл: тэр компьютер дээрээ 9-р хэсгийн 3-р алхмаас. Нөөцлөлтөөс хойш оруулсан бүхэн алдагдах тул үүнийг эзэмшигч шийднэ.

## 9. Компьютер эвдэрвэл

Компьютерээс гарсан сүүлийн нөөцөөс хойших бүх зүйл алдагдана. Дэлгүүрийн PosAPI компьютерт гаргасан баримтууд нь үлдэнэ. Энэ хооронд кассууд хуучин программаараа ажиллана.

1. Ubuntu, Docker, git-тэй компьютер бэлдэж, router дээр ижил хаягийг (`192.168.1.152`) өгнө. Хамгийн сүүлийн шөнийн хавтсыг USB дискнээс эсвэл эзэмшигчийн компьютерийн `Documents\Bto-backups\store`-оос авч шалгана: хавтас дотроо `sha256sum -c SHA256SUMS`.
2. `git clone https://github.com/ez4puljin/Bto.git ~/bto && cd ~/bto && git checkout $(cat <шөнө>/commit.txt)`. Юу ч асаахаас өмнө хоёр файлыг буцааж тавина: `cp <шөнө>/store.env deploy/store/.env && cp <шөнө>/edge.env deploy/edge/.env && chmod 600 deploy/store/.env deploy/edge/.env`.
3. Төв. Эхний команд бүтээж, эрхүүдийг файлын нууц үгээр үүсгээд хоосон сан дээр зогсоно. Дараагийн командууд тэр хоосон санг нөөцийнхөөр солино (**зөвхөн өгөгдлийн сан нь хоосон эсвэл алдагдсан компьютер дээр**):

   ```bash
   bash deploy/store/setup.sh
   $S stop api worker web
   $S exec -T postgres dropdb -U postgres --if-exists bto
   $S exec -T postgres createdb -U postgres -T template0 -E UTF8 --locale-provider=icu --icu-locale=und bto
   $S exec -T postgres pg_restore -U postgres -d bto --exit-on-error < <шөнө>/centre.dump
   $S run --rm provision
   ```

4. Файлууд: `docker run --rm -v bto-store_storage:/data/storage -v <нөөц>/storage:/from:ro bto-api:store-local cp -a /from/. /data/storage/`.
5. `bash deploy/store/setup.sh` (өгөгдлийг олж, асаана). Дараа нь одоогийн хувилбарт буцна: `git checkout main && git pull && bash deploy/store/setup.sh`.
6. Edge: `bash deploy/edge/setup.sh`, дараа нь санг нь холболт, кассын бүртгэлтэй нь буцаана:

   ```bash
   $E stop kiosk edge
   $E exec -T edge-db dropdb -U edge --if-exists tugeel_edge
   $E exec -T edge-db createdb -U edge -T template0 -E UTF8 tugeel_edge
   $E exec -T edge-db pg_restore -U edge -d tugeel_edge --exit-on-error < <шөнө>/edge.dump
   bash deploy/edge/setup.sh
   ```

   Эвдэрсэн компьютерийн edge төв рүү илгээж амжаагүй, шөнийн нөөцөд ч ороогүй борлуулалтыг баримтаас нь дахин оруулна.
7. 4-р хэсгийг дахин хийнэ: цагийн тохиргоо, нэг удаагийн нөөцлөлт, сэргээх сургуулилт.

## 10. Ажилчдын апп гаднаас холбогдох (ADR-0188)

Ажилчдын апп болон (ADR-0189-өөс хойш) оффисын вэб гаднаас нэг хаягаар нээгдэнэ. Энэ нь PC дээр аль хэдийн ажиллаж буй эзэмшигчийн Cloudflare tunnel-ээр явна. Хаяг нь зөвхөн `deploy/store/.env`-ийн `STORE_PUBLIC_COUNTRIES`-д бичсэн улсаас (анхдагч `MN`; олон бол `MN|KR`; дараа нь `bash deploy/store/setup.sh`) ирсэн хүсэлтэд хариулна: бусад нь 403 авна, гадаадад яваа ажилтны апп ч мөн адил. Касс дотоод сүлжээнд үлдэнэ. Нэмэлт хамгаалалт Cloudflare дээр: Security → WAF → Custom rules → `(http.host eq "app.puljika.site" and ip.src.country ne "MN")` → Block.

1. **Эхлээд:** энгийн нууц үг бүрийг солино, хамгийн түрүүнд админуудынхыг (хаяг нээгдмэгц интернэтээс хэн ч утасны дугаар, нууц үг туршиж болно).
2. **Эзэмшигч, Cloudflare-ийн самбарт** (Zero Trust → Networks → Tunnels → `bto.puljika.site`-г зөөдөг tunnel → «Public Hostname» → «Add a public hostname»): subdomain `app`, domain `puljika.site`, type `HTTP`, URL `localhost:80`. Хадгална. PC дээр юу ч суулгахгүй, хуучин ERP-ийн мөрийг хөндөхгүй.
3. **PC дээр** хаягийг төвийн тохиргоонд бичээд (нууц биш) төвийг дахин асаана:

   ```bash
   cd ~/bto
   grep -q '^STORE_PUBLIC_HOST=' deploy/store/.env \
     && sed -i 's/^STORE_PUBLIC_HOST=.*/STORE_PUBLIC_HOST=app.puljika.site/' deploy/store/.env \
     || echo 'STORE_PUBLIC_HOST=app.puljika.site' >> deploy/store/.env
   bash deploy/store/setup.sh
   ```

4. **Гаднаас шалгах** (дата-тай утас эсвэл өөр компьютер):

   ```bash
   curl -s https://app.puljika.site/health            # {"status":"ok",…}
   curl -s -o /dev/null -w '%{http_code}\n' https://app.puljika.site/   # Монголоос 200, гадаадаас 403
   ```

5. **Утаснууд:** ажилчдын апп дээр «Серверийн хаяг» → `https://app.puljika.site`; эсвэл `BTO_SERVER=https://app.puljika.site pnpm mobile:apk`-аар бүтээсэн аппыг тараана. Дэлгүүрийн Wi-Fi дээр интернэт тасарсан үед хаяг нь `http://192.168.1.250`.

**Хаах:** Cloudflare-ийн самбараас public hostname-ийг устгана (тэр дороо), эсвэл `STORE_PUBLIC_HOST`-ыг хоосолж `setup.sh` ажиллуулна.

## 11. Утас руу сэрэмжлүүлэг (ADR-0195)

Харуул (`deploy/store/watch.sh`) системийг минут тутам гаднаас нь шалгаж, асуудал гарахад эзэмшигчийн Telegram руу бичнэ: эхлэхэд нэг удаа, үргэлжилж байвал 6 цаг тутам, засагдахад нэг удаа. `setup.sh` timer-ийг нь суулгадаг; эзэмшигч ботоо нэг удаа холбох хүртэл чимээгүй байна:

1. Telegram-д **@BotFather**-ийг нээж `/newbot` гэж бичээд ботын нэр, хэрэглэгчийн нэр өгнө; тэр token өгнө.
2. PC дээр: `bash ~/bto/deploy/store/alerts-setup.sh`. Асуухад token-оо буулгана (дэлгэцэд харагдахгүй), дараа нь сэрэмжлүүлэг авах утаснаасаа шинэ бот руу дурын үг бичээд Enter дарна; олдсон чатыг батална. Туршилтын мэдэгдэл ирнэ.

Юуг мэдэгдэх вэ: төв хариу өгөхгүй байх, аль нэг хэсэг зогссон эсвэл дутуу байх (нэмэлт процессуудыг тоолно), диск 85 % хүрэх, санах ой дуусах, шөнийн нөөцлөлт бүтэлгүйтэх эсвэл хийгдээгүй байх, 10 минутад 10 серверийн алдаа, тайлан «түр хүлээнэ үү» хариу авах, мөн «PC дахин аслаа» гээд хэр удаан унтарсныг.

```bash
bash ~/bto/deploy/store/watch.sh --check            # одоо юу харж байна; юу ч илгээхгүй
bash ~/bto/deploy/store/watch.sh --test             # нэг туршилтын мэдэгдэл
systemctl --user list-timers bto-watch.timer        # дараа хэзээ ажиллах
journalctl --user -u bto-watch -n 20                # сүүлийн тойргууд
```

Тоонууд нь `deploy/store/.env`-ийн `STORE_ALERT_*` (`.env.example`-д жагсаасан). PC унтарсан үед PC өөрөө мэдэгдэж чадахгүй: `STORE_ALERT_HEARTBEAT_URL`-д «dead man's switch» үйлчилгээний хаягийг тавибал тойрог зогсоход тэр үйлчилгээ мэдэгдэнэ. **Чимээгүй болгох**: `STORE_ALERT_TELEGRAM_*` хоёр мөрийг устгана; **бүрмөсөн болих**: `systemctl --user disable --now bto-watch.timer`.

## Алдаа гарвал

- **Хуулах үед «the target is not empty».** Төв систем хуулахаас өмнө ассан байна (api анх асахдаа эрхийн жагсаалтыг бичдэг). Жинхэнэ өгөгдөл ороогүй компьютер дээр: `$S stop api worker web`, дараа нь 9-р хэсгийн 3-р алхмын `dropdb`, `createdb` мөрүүд, `$S run --rm provision`, `$S run --rm migrate`, тэгээд дахин хуулна. Хэн нэгэн ажилласан систем дээр хэзээ ч бүү хий.
- **`provision` өгөгдлийн санд нэвтэрч чадахгүй.** `deploy/store/.env` устаж шинээр үүссэн, харин сан хуучин нууц үгээ хадгалсан байна. Нөөцөөс хуучин файлыг (`store.env`) буцааж тавина. Эсвэл шинэ файлын нууц үгийг сангийн дотроос, дэлгэцэд гаргалгүй тохируулна:

  ```bash
  PW=$(grep '^POSTGRES_PASSWORD=' deploy/store/.env | cut -d= -f2-)
  echo "ALTER ROLE postgres PASSWORD :'pw'" | $S exec -T postgres psql -U postgres -v pw="$PW"
  unset PW
  ```

- **Өөр компьютерээс хуудас нээгдэхгүй.** `$S ps` (бүх хэсэг `healthy`), `sudo ufw allow 80/tcp`, компьютерийн хаягийг шалгана.
- **Бүтээлт санах ой дутаж зогсоно.** Бүтээх хооронд edge-ийг зогсооно (`$E stop kiosk edge`, дараа нь `bash deploy/edge/setup.sh`). Ажлын бус цагаар хийнэ.
- **Ажилтны апп.** Энэ төвд зөвхөн дэлгүүрийн Wi-Fi-аар, түүнд зориулж бүтээсэн хувилбараар холбогдоно (эзэмшигчийн компьютерт `BTO_SERVER=http://192.168.1.152 pnpm mobile:apk`). Хамгийн сүүлд нийтэлсэн APK: `http://192.168.1.152/api/v1/app-releases/staff/apk`. Bto300 туршилтын сервер дээрээ үлдэнэ.
