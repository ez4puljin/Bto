# ADR-0246: Supplier invoice base prices and explicit location uplifts

| | |
|---|---|
| Status | Accepted, local implementation |
| Date | 2026-11-23 |
| Decider | Owner: printed invoice prices, latest posted receipt, manual edits overwritten by the next receipt with notification |
| Amends | ADR-0048 and ADR-0099 for configured supplier/location prices; accounting rules in ADR-0236 and expiry evidence in ADR-0245 remain |

## Decision

1. A product has one canonical base selling price per base unit. An enabled supplier rule computes it from the printed invoice price before discount, regardless of purchase promotions or free-goods accounting. Percentage, fixed whole-MNT uplift, their combination and the existing rounding choices are supported. No stock average, net payable or VAT-exclusive accounting amount replaces that printed basis.
2. Printed acquisition references are recorded separately from accounting on receipt lines, as an amount and its original unit factor. Counting a partial arrival in another unit retains the reference ratio. Free-goods inventory cost stays zero. Unknown old references remain null. A genuine printed zero is known: a fixed uplift may still produce a positive selling price.
3. Computation keeps the exact printed amount/base-quantity ratio until the final rounding: `(amount * (100 + percent) + fixed * qtyBase * 100) / (qtyBase * 100)`. A normalized display price is not rounded and reused as a monetary source. Conflicting ratios for the same product in one receipt produce a visible skipped-price result; no line, average or zero is guessed.
4. The latest successfully posted receipt, not its printed calendar date, establishes the per-product source watermark. Every posted receipt advances it, including unconfigured suppliers and missing printed prices. An enabled rule's values/version are frozen at that milestone. Missing, conflicting or out-of-range sources leave the current selling price in force and record the reason; receiving valid stock need not fail for a missing selling-price reference.
5. A receipt posted unpriced may establish its base when its first printed pricing is completed. That callback applies only while the receipt is still the latest source and no manual base change followed its posting. Unchanged rounded unit/amount echoes retain the original reference ratio. The first checked invoice may correct a paid line's printed pair or fill a previously unknown pair; a known free-goods reference remains frozen. After first pricing, printed pairs are immutable and later accounting revaluations do not reprice sales. Unique receipt/phase/product events make retries harmless.
6. A price clerk may set a current base price without a receipt, with a reason and expected current price/event. Legacy price dialogs, bulk price imports and import reversals also participate in manual source tracking. The next posted receipt may overwrite that manual value; no manual price lock is added. A stale manual form is rejected even when a price changed away and back to the same amount.
7. Canonical prices are written through `ProductPricesService` into the existing dated `product_prices`, preserving the applicable profile and whole unit. A previously unpriced product may receive a neutral zero-uplift profile; this invents no acquisition amount and does not complete its catalog registration. Current automatic/manual base writes void prior future price schedules before writing an open-ended current base, so an older schedule cannot silently restore itself. All replaced rows remain in history. Later explicitly created schedules remain explicit future intent.
8. A warehouse may explicitly choose BASE or ADDITIONAL. BASE uses the canonical price for every quantity. ADDITIONAL applies a nonnegative percentage/fixed uplift to that base, rounded no lower than the base. Both supersede legacy loose/retail profile increments for that location. Unconfigured locations retain the existing profile behavior. Immutable day-effective location revisions preserve historical-date quotes; previously frozen sales documents retain their own facts.
9. Real source warehouses are supplied per line for mixed-source orders; a pipeline transfer destination is not a price source. Tills use their warehouse's safe location settings in the offline snapshot. The same shared resolver prices the center, edge and previews. Known-location labels, shop cards, pack-deal probes and price sorting use the same derived price. Unknown contexts retain the legacy fallback.
10. The normal minimum base is distinct from approved expiry fixed prices. Ordinary product/category/order discounts and coupons may consume only the available uplift. Complete N+M discounts remain when their full cut fits above the floor; an impossible full bonus is omitted instead of reporting clipped free quantities. Below-threshold paid-entry hints obey the same test. Approved expiry barcodes retain their independent fixed price and their sold-only payroll loss basis.
11. One global supplier-price gate precedes price product/table locks and receipt inventory locks. Manual/configuration writes, receipt posting and first-pricing callbacks share it. The source event, canonical price, watermark and internal notification are in the receipt transaction: a failed receipt or notification writes none of them. A pricing-owned observer port avoids a service-constructor cycle while covering old price entry points.
12. Changed receipt prices and supported warnings create durable internal bell notifications for price managers, including overwritten manual values. Stable immutable event IDs distinguish POST from a legitimate later FIRST_PRICED result. Payload samples are bounded and link to the full receipt-change history. No SMS, email, customer notice or APK publication is part of this change. API and worker composition bind the same adapter; isolated pricing modules may omit it.
13. Supplier rules are managed by `pricing.manage`; location changes also require warehouse write scope. Manual prices require `pricing.prices.manage`. Selling prices and their source summaries are readable to signed-in staff, while printed acquisition amounts require `inventory.costs.manage`. Generic audit and inbox payloads contain no printed purchase amount or accounting cost.
14. Migration `0130_supplier_base_location_prices` is additive. Existing supplier/location rules are not invented and existing prices are not recalculated during migration. New event and location revision history is append-only; finite positive whole-MNT prices, rule versions, reference pairs and state/event product consistency are guarded in SQL. Applied SQL and snapshots are unchanged. No demo data or existing price history is generated by this migration.

15. Receipt-price notifications live in the additive `user_price_notifications` sidecar. The existing `user_notifications` table and its three-kind CHECK remain unchanged. Both tables allocate positive IDs from the existing identity sequence without resetting or changing its ownership. Column-level app grants allow inserting only recipient, stable event key and payload; IDs and timestamps remain database defaults, and only `read_at` is mutable. A unique event-key/recipient pair makes retries harmless. The inbox merges both streams in one SQL snapshot before applying its existing numeric-ID cursor and page limit; old cursors, unread counts and user-scoped idempotent reads keep their meaning. Receipt notification writes remain in the source receipt transaction.

## Validation

Shared tests cover explicit base/additional pricing, packs, legacy fallback, discount/coupon floors, viable and impossible paid-entry bonuses, mixed locations, exact source ratios and the expiry exception. API tests cover rights, optimistic configuration/manual conflicts, legacy manual observers, current prices, labels, dated location rules and superseded schedules. Integrity tests cover append-only evidence, raw nonfinite values, state linkage and rule revisions. Receipt/edge integration is validated with the corresponding source and adapter work.
