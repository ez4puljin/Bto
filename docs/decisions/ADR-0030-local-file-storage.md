# ADR-0030: Local file storage until go-live: API-signed URLs, public images, owner-confirmed files

| | |
|---|---|
| Status | Accepted |
| Date | 2026-10-11 |
| Deciders | Owner, Claude (Claude Code session) |
| Amends | ADR-0014 #2, #3, #5 (presigned Spaces URLs; the local driver's behaviour) |

## Context

ADR-0014 stores files on DigitalOcean Spaces through presigned URLs, with a filesystem driver for development. ADR-0026 moved every hosting resource, Spaces included, to the go-live phase, so for about a year all files (product images first, workbooks for imports in week 4) live on the owner's machine. The local driver therefore has to behave like the Spaces one where it matters (the client uploads with a URL the server signed, nothing else authenticates the upload, files of a document are confirmed by the module that owns the document) while being served by the API itself. Product images appear in lists that TanStack Query caches for minutes; URLs that expire would break thumbnails. The worker never holds `JWT_SECRET`.

## Decision

1. **Driver selection.** `STORAGE_DRIVER` defaults to `spaces`, which refuses to start until the go-live phase builds it. Development, tests, the OpenAPI export and the rehearsal stacks set `local` with `STORAGE_LOCAL_DIR` (`<repo>/.data/storage` locally).
2. **Layout.** `<root>/public/<name>`, `<root>/private/<name>`, uploads first land in `<root>/.tmp` on the same volume and are renamed into place. Object names are generated by the server (`<uuid>.<ext>`) and validated by a strict pattern before any file-system call.
3. **Upload.** `POST /files/presign {kind, contentType, sizeBytes}` checks the kind's permission, type and size limit from `@tugeel/shared/files`, inserts a `files` row (PENDING) and returns a URL to `PUT /files/local/<name>?exp&sig`. The signature is HMAC-SHA256 over method, name, expiry, content type and size, keyed by `HKDF(JWT_SECRET, "tugeel storage url v1")`, valid 15 minutes. The PUT route is public; it checks the signature, the exact `Content-Type` and size, streams the body to disk while hashing it, verifies the image signature bytes, records `uploaded_at` and `sha256` once (a second upload is 409) and leaves no file behind on any failure. Clients upload with a plain `fetch`, never with the `Authorization` header.
4. **Attach.** The owning module calls `StorageService.verifyUploaded` before its transaction (the Spaces driver will make an HTTP HEAD there) and `StorageService.confirm(tx, fileId, kind)` inside it, which sets READY. Only identity writes `files`; removal marks DELETED and the bytes go with a later cleanup job.
5. **Reads.** Files of public kinds (product images) are served at the stable path `/api/v1/files/public/<name>` once READY, with `Cache-Control: public, max-age=31536000, immutable`; the go-live phase swaps the prefix for the CDN. Private kinds get short-lived signed download URLs when the first one exists. Access logs drop public file reads and redact `sig`.
6. **Processes.** `StorageService` (rows, disk, verify, confirm) lives in `IdentityModule` for the api and the worker; the URL signer and the file routes live in `IdentityHttpModule` (api only).

## Alternatives considered

| Alternative | Why rejected |
|---|---|
| Multipart uploads through an authenticated JSON route | A second body parser on the api (the JSON-only rule is a CSRF defence, ADR-0027) and a code path the Spaces driver will not have. |
| A separate signing secret | One more secret to generate and rotate for a local-only feature; HKDF from `JWT_SECRET` gives an independent key. |
| Signed URLs for product images too | URLs cached in lists expire; immutable public names are what the CDN will serve anyway. |
| MinIO in Docker as a local S3 | Another container and credential for a single developer; the API-signed driver is a few hundred lines with tests. |

## Consequences

**Positive.** Uploads, confirmation and public reads work identically in development and after go-live; images cache forever; the worker can read files without the secret.

**Negative.** File bytes pass through the API process until go-live (ADR-0014's "never proxies" applies from then on); rotating `JWT_SECRET` invalidates upload URLs issued in the last 15 minutes; PENDING uploads that are never attached accumulate until the cleanup job exists.
