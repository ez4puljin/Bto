# ADR-0003: PostgreSQL 18 as the only datastore, Drizzle ORM with hand-edited SQL migrations

| | |
|---|---|
| Status | Accepted |
| Date | 2026-10-09 |
| Deciders | Owner, Claude (Claude Code session) |
| Amended by | ADR-0024 ("migration 0001" = foundation migration `0000_foundation` + guards in the owning module's first migration) |

## Context

The core logic is SQL-shaped: row locks in a deterministic order, upserts with arithmetic, CTEs, window functions, exclusion constraints. The owner must be able to read what the database does, and the AI agent must not be able to silently remove database-level guards. Mongolian Cyrillic search and case folding (Ө, Ү, Ё) depend on the cluster's collation. The hosting budget is small: the DigitalOcean Managed PostgreSQL entry plan has a low backend-connection limit, and four long-running Node processes with default pool sizes would exhaust it.

Facts (`docs/architecture.md` §0, §13): PostgreSQL 18 (GA 2025-09-25, supported to 2030-11) offers `uuidv7()`, virtual generated columns and temporal constraints; PostgreSQL 19 is not GA. Drizzle ORM `latest` is 0.45.x with drizzle-kit 0.31.x; Drizzle 1.0 is still a release candidate that removed the RQB v1 API and changed the casing API. Prisma 8 is a release-candidate re-architecture; Prisma 7 needs raw SQL for `FOR UPDATE`.

## Decision

1. **PostgreSQL 18** on DigitalOcean Managed Databases, region SGP1 (17 only if 18 is not offered at cluster creation; 19 is skipped in year one). Extensions: `pg_trgm` (search) and `btree_gist` (price-rule exclusion constraint, ADR-0009).
2. **Encoding and collation.** The production database is created with `ENCODING 'UTF8'` and an ICU default collation (`LOCALE_PROVIDER icu`, `ICU_LOCALE 'und'`), never the `C` locale. Local and CI containers use the same settings. The integration-test harness and the API boot sequence assert `SELECT lower('ӨҮЁ') = 'өүё'` and fail loudly if case folding does not cover Mongolian letters. Search additionally uses an application-maintained `search_text` column (NFKC, lowercased, Cyrillic/Latin look-alike map) so that search never depends on the collation alone (ADR-0011).
3. **Drizzle ORM 0.45.x + drizzle-kit 0.31.x** with the `pg` driver. Schema lives in each module's `schema.ts`; one PostgreSQL schema (`public`). Migrations are **SQL files** under `apps/api/src/db/migrations/`, generated by `drizzle-kit generate` and then **hand-edited** to add CHECK constraints, partial unique indexes, `EXCLUDE` constraints, `REVOKE`s and triggers. Applied migrations are never edited. Drizzle is not upgraded to 1.0 until `latest` points to it, and then only in a dedicated session.
4. **`drizzle-kit push` is forbidden.** There is no `db:push` script; CLAUDE.md lists it under NEVER. `push` diffs `schema.ts` against the live database and drops objects that are not in `schema.ts`, which is exactly the hand-edited guard layer. The only workflow is `db:generate` -> edit -> `db:migrate`. CI runs `drizzle-kit check` (snapshots vs migrations) **and** a guard-existence test: as role `app`, `UPDATE stock_ledger ...` and `DELETE FROM stock_ledger ...` must fail (ADR-0016).
5. **Two database roles.** `app` (runtime; no DDL, no UPDATE/DELETE on append-only tables) and `migrator` (runs migrations from the api container entrypoint). Both are created once per environment by `scripts/db-provision.ts` (`pnpm db:provision`, admin connection), never by a migration (`docs/architecture.md` §10.5). Secrets for both live in `/opt/tugeel/.env`, never in git.
6. **Connection pool budget** (per process, `max` of the `pg` pool): production `api` 6, production `worker` 3, pg-boss 2 per process in addition. **Staging runs against a local `postgres:18` container on the droplet**, not on the managed cluster, so the cluster serves only production. The cluster's exact backend-connection limit is recorded in `deploy/runbook.md` at creation, and the budget is also written in CLAUDE.md. If the limit is ever approached, the first remedy is DigitalOcean's built-in connection pooler in transaction mode for the `api` pool (never for pg-boss or the migrator).
7. **Decimal columns** (`NUMERIC`) are mapped by a Drizzle custom type that returns `Decimal` from decimal.js, never a JS number or a raw string (ADR-0010).
8. **Primary keys** are `bigint identity`; UUIDs (`uuidv7()`) only for tokens, idempotency keys and payment-intent ids (`sender_invoice_no`, ADR-0018). No Redis, no search service, no second datastore.

## Alternatives considered

| Alternative | Why rejected |
|---|---|
| Prisma 7 | Driver-adapter and config churn; raw SQL needed for `FOR UPDATE`, CTEs and exclusion constraints. |
| Prisma 8 RC | New contract/query API still renaming between release candidates in October 2026. |
| TypeORM | Weaker typing, migration generator drifts from entities. |
| Kysely | Excellent SQL builder but no migration generator and smaller documentation footprint. |
| One PostgreSQL schema per module | Clearer ownership but more ceremony for cross-module FKs and reporting views. |
| Supabase / Neon | Extra abstractions; Singapore latency is the same; DO already provides backups and PITR. |
| `C` locale with search handled fully in app code | Still breaks `lower()`/`ILIKE` everywhere else in the system. |

## Consequences

**Positive.** Typed SQL with readable migrations the owner can inspect; database-level guards survive wrong application code; one managed service to pay for. `uuidv7()` and virtual generated columns are available without extensions.

**Negative.** Hand-edited migrations require discipline (`drizzle-kit check` and the guard test are the safety net). The small pool budget means a slow query blocks others sooner; it must be measured, not guessed.

**Follow-ups.**
- `scripts/db-provision.ts` (`pnpm db:provision`, run with the admin connection) creates roles `app` and `migrator` once per environment; migration `0001` creates the extensions, the collation assertion function and the ledger guards (GRANT/REVOKE, trigger), never roles (`docs/architecture.md` §5.3, §10.5).
- `deploy/runbook.md`: record the cluster's connection limit and the pool budget on creation day.
