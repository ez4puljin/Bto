# ADR-0022: POS print agent: a polling Node service on the supermarket POS PC

| | |
|---|---|
| Status | Proposed (to be accepted before delivery 9 starts); for the supermarket's tills superseded by ADR-0065 (receipts printed from Chrome through the printer's Windows driver); stays planned for the label printer's phase 2 |
| Date | 2026-10-09 |
| Deciders | Owner, Claude (Claude Code session) |

## Context

The supermarket POS is a screen in the web admin (ADR-0002, ADR-0021); the API runs in Singapore (ADR-0012); the receipt printer is an Ethernet 80 mm ESC/POS device on the supermarket LAN with a cash drawer attached to it. Facts (`docs/architecture.md` §9, §13): browsers cannot open raw sockets to port 9100; WebUSB is blocked by Windows printer drivers; QZ Tray prints silently only with a certificate bought from QZ Industries (storefront snippets show $599-749/year) or a self-managed root certificate installed on each POS PC, and otherwise shows warning dialogs; the e-Barimt receipt with QR and lottery must print at checkout, and `lottery`/`qrData` may exist only in memory on the way to the printer (ADR-0017). Without a decision, delivery 9 would improvise a fourth deployable.

## Decision

1. **A small Node print agent lives in `packages/printing/agent`** (about 100 lines, same repository, same lint and CI, TypeScript, pinned Node 26 runtime (ADR-0023)). It is one process with one loop.
2. **Pull, never push.** The agent **polls the API over HTTPS** (`GET /api/v1/print-jobs/next?station=<id>`, long-poll up to 20 s) with a station token issued per POS PC (`print_stations` table: `id`, `branch_id`, `name`, `token_hash`, `printer_host`, `printer_port`, `last_seen_at`). **No inbound ports** on the POS PC and no Tailscale dependency for printing. The agent acknowledges each job (`POST /print-jobs/:id/ack` with `status` PRINTED/FAILED and an error string).
3. **Jobs** are rows in `print_jobs` (`id`, `station_id`, `kind` RECEIPT/LABEL/DRAWER, `payload bytea` = the ESC/POS or TSPL bytes generated server-side, `status` QUEUED/PRINTING/PRINTED/FAILED, `created_at`, `acked_at`, `attempts`). Payload bytes are generated by the API at checkout from the in-memory receipt (including rendered QR and lottery raster) and **nulled on ack**; a job row older than 10 minutes is expired, and the POS screen offers a reprint that regenerates from the ДДТД without the lottery.
4. **Transport.** The agent writes the bytes to `printer_host:9100` with Node `net`, waits for the socket to drain, closes, and acks. A **cash-drawer pulse** job sends the ESC/POS `pulse` sequence the same way. Failures (connection refused, timeout 5 s) are reported in the ack and shown on the POS screen; the API retries a job at most 3 times on explicit request from the cashier, never automatically for receipts (to avoid double prints).
5. **Installation.** The agent runs as a **Windows service registered with `nssm`** on the POS PC, started at boot, with `API_URL`, `STATION_TOKEN`, `PRINTER_HOST` in a local config file. Updates are a copy of the built bundle plus `nssm restart`; `deploy/pos-agent/` holds the install script and runbook. The service logs to a local rotating file and reports `last_seen_at` on every poll, which the admin shows as station health.
6. **Scope.** The agent handles raw bytes only; it knows nothing about receipts, prices or e-Barimt. It serves the supermarket POS printer and, in label phase 2, the warehouse label printer (ADR-0021) through a second station.

## Alternatives considered

| Alternative | Why rejected |
|---|---|
| QZ Tray | Annual certificate cost or a self-managed root certificate on every POS PC plus warning dialogs; a second vendor's update cadence; still needs a signed payload per print. |
| Browser print dialog | No cash-drawer pulse, driver-dependent Cyrillic and QR rendering, a dialog per sale. |
| API opens a socket to the printer over Tailscale | Needs a tailnet subnet router at the supermarket and an inbound path to the LAN; printing would depend on Tailscale and the office box topology. |
| Agent with an inbound HTTP port called by the browser | Mixed-content and certificate problems on `localhost`, firewall rules on the POS PC, no station authentication. |
| Native POS app on Sunmi hardware | A second POS codebase for one site (ADR-0021). |

## Consequences

**Positive.** No inbound ports, no certificates, no vendor; the agent is testable in CI with a fake printer socket; receipts and drawer pulses share one path; station health is visible in the admin.

**Negative.** A fourth deployable (small, but with its own install runbook and update step); receipt bytes transit through the database for up to 10 minutes (payload nulled on ack; never contains stored lottery beyond that window, documented in the e-Barimt runbook); the POS PC must run Node and `nssm`.

**Follow-ups.** Before delivery 9: accept this ADR, build the agent and the `print_jobs`/`print_stations` tables, test against the supermarket's actual printer with the Mongolian test string and a QR. Delivery 9: integrate with POS checkout and shift close.
